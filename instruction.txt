WHAT WAS SET UP
---------------
1. Frontend .env file
   - File: ./.env  (repo root). Holds the Firebase config with variable names
     FIREBASE_API_KEY, FIREBASE_AUTH_DOMAIN, FIREBASE_PROJECT_ID,
     FIREBASE_STORAGE_BUCKET, FIREBASE_MESSAGING_SENDER_ID, FIREBASE_APP_ID,
     FIREBASE_MEASUREMENT_ID.
   - Template: ./.env.example
   - NOTE: A browser can NEVER read a .env file. Firestore/Firebase config is
     meant to be public anyway, but you asked to keep it out of the JS source.
     So the Express server (/server/server.js) loads ./.env and exposes the
     values to the browser at the route:
        GET /api/config/firebase
     and script.js fetches that route before initializing Firebase.
   - script.js no longer contains the hardcoded config.

2. Server changes (server/server.js)
   - Loads BOTH env files:
        ./.env        (frontend/Firebase config)
        ./server/.env (DATABASE_URL, ADMIN_EMAILS, PORT)
     Real environment variables are never overwritten by dotenv, so on Vercel
     the dashboard vars win, which is what we want.
   - New public endpoint /api/config/firebase.
   - Server still serves the static frontend AND the API in one app.

3. Prisma (server/prisma/schema.prisma)
   - Added binaryTargets = ["native", "rhel-openssl-3.0.x"]
     "native" keeps Windows local dev working; "rhel-openssl-3.0.x" is what
     Vercel Node.js Functions need. Run `prisma generate` after pulling this.

4. Vercel config
   - ./package.json            (root): lets Vercel install deps + run
     `prisma generate --schema=server/prisma/schema.prisma` automatically.
   - ./vercel.json             : builds server/server.js with @vercel/node and
     includes ALL files so the Express app can serve the static frontend too.
   - ./.vercelignore           : keeps node_modules / lockfiles out of uploads.

CAN YOU HOST FRONTEND AND BACKEND TOGETHER ON VERCEL?
-----------------------------------------------------
YES. They are one single deployment. Your Express backend does two jobs:
it serves the static HTML/CSS/JS (frontend) AND handles /api/* (backend).
vercel.json sends every request to the Express serverless function, which
already routes static files and API calls. You only manage ONE Vercel project.

NOTE ON "FIREBASE SECRETS"
--------------------------
Firebase config keys for web apps are not actually secret (they are exposed to
every visitor's browser by design; real protection is your Firebase Security
Rules). They are now stored in .env so the JS source stays clean, and so you
can change them per environment without touching code.

TROUBLESHOOTING
---------------
- Build fails with "prisma: command not found":
  prisma is declared in the root package.json dependencies - it must stay there.
- Runtime "could not locate the Query Engine for runtime":
  run `pnpm prisma generate` locally after pulling the schema change
  (binaryTargets are already set), then push again.
- Firebase login loops / "This domain isn't authorized":
  add the deployed domain in Firebase console Authorized domains (step 5).
- /api/config/firebase returns nulls:
  the FIREBASE_* variables are missing in Vercel - add them (step 3).
- CORS errors: not expected because frontend and API are same origin on Vercel.
